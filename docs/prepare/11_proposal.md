# 11 — Proposal (ส่งอาจารย์, milestone สัปดาห์แรก)

## English (ส่งฉบับนี้)
**BasisMedic: an evaluated RAG agent for SAP Basis incident triage.**
Junior SAP Basis administrators on call often face an error — an ABAP short dump, a cancelled background job, a failed transport import, a locked user, a broken RFC connection — without knowing which transaction (T-code) to open first, and lose time searching scattered documentation. BasisMedic takes a pasted error log and returns a validated JSON triage: the incident category (8 categories + out-of-scope), the T-codes to check in order, step-by-step checks, and citations to the runbook sections it used. The corpus is ~16 runbooks I write myself, summarised from public SAP Help Portal / SAP Learning pages with references, plus a T-code allow-list. Techniques: (1) structured output with Pydantic validation and a repair loop, (2) RAG with citations using hybrid retrieval (BM25 + bge-m3 fused with RRF, because error codes such as TSV_TNEW_PAGE_ALLOC_FAILED are exact rare tokens), (3) retrieval evaluation, and (4) a tool-calling agent loop (search_runbook, lookup_tcode) with max-steps and repeated-call guards, served through a FastAPI backend (REST + SSE progress streaming) and a Next.js chat-style web UI. Evaluation: 30 hand-written synthetic incident logs (easy/medium/hard, Thai, out-of-scope, mixed) plus a 10-case dev set for tuning; metrics are recall@3 and MRR for retrieval, and category accuracy and T-code recall end-to-end; baselines are BM25-only, dense retrieval with naive fixed-size chunks, and the LLM without retrieval. I will report one measured improvement each for chunking (fixed vs section-based), retrieval mode, and the min_score floor.

## ภาษาไทย (ไว้อ่านเอง)
BasisMedic คือ agent แบบ RAG ที่ประเมินผลได้ สำหรับช่วย triage incident ของ SAP Basis ผู้ดูแลระบบมือใหม่ที่เข้าเวรมักเจอ error (short dump, job ถูก cancel, transport import ล้ม, user ถูกล็อก, RFC ใช้ไม่ได้) แล้วไม่รู้ว่าต้องเปิด T-code ไหนก่อน ต้องค้นเอกสารที่กระจัดกระจาย BasisMedic รับ log แล้วคืน JSON ที่ validate แล้ว: ประเภทปัญหา (8 + นอกขอบเขต), T-code ที่ควรเปิดตามลำดับ, ขั้นตอนตรวจ, และอ้างอิง runbook ที่ใช้ Corpus คือ runbook ~16 ไฟล์ที่เขียนเองจากเอกสาร SAP สาธารณะ + รายการ T-code ที่อนุญาต ใช้เทคนิค structured output, RAG แบบ hybrid (BM25 + bge-m3 + RRF), retrieval evaluation และ agent loop ที่มี tools 2 ตัว ประเมินด้วย log 30 ข้อ (+dev 10) วัด recall@3, MRR, category accuracy, T-code recall เทียบ baseline BM25-only, dense+chunk แบบ naive และ LLM ที่ไม่มี retrieval
